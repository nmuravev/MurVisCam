# Камеры: внешние и встроенные, выбор источника потока

## Типы камер

| Тип | Пример | Особенности |
|---|---|---|
| Встроенная задняя | SoC-камера телефона | всегда доступна; ориентация/FOV фиксированы |
| Внешняя USB-UVC | `LENS_FACING_EXTERNAL` (USB-камера, подвес, ствольная камера) | hot-plug; требуется `android.hardware.usb.host` (manifest, required=false) |

Manifest объявляет `android.hardware.camera.external` и `android.hardware.usb.host`
как необязательные — приложение ставится на устройства без внешней камеры.

## Явный выбор из выпадающего списка

В нижней панели `CameraActivity` есть **Spinner источника видео**
(`R.id.camera_source_spinner`, `setupCameraSourceSpinner()`):

- список содержит все камеры `CameraManager.getIdList()` с человекочитаемыми
  метками: `Внешняя USB #N (<id>)`, `Задняя встроенная`, `Передняя`, `Логическая`;
- выбор пользователя имеет приоритет над автоматикой: `onItemSelected` пишет
  `AppConfiguration.cameraSource` (EXTERNAL/BUILTIN по facing выбранной камеры),
  выполняет `resetAll()` у DroneMotionEstimator, гасит HUD и переконфигурирует
  preview-поток на новой камере; старая камера корректно закрывается до открытия
  новой;
- при старте spinner **предвыбирает фактически привязанную камеру** (переменная
  `lastBoundCameraId`, выставляется внутри `chooseCamera()`);
- горячее извлечение внешней камеры → срабатывает fallback-политика `chooseCamera()`.

## Политика chooseCamera() (fallback, когда spinner не трогали)

```
AUTO     → pass1: LENS_FACING_EXTERNAL; если нет — встроенная задняя
EXTERNAL → только внешняя; если недоступна — warn + встроенная задняя
BUILTIN  → сразу встроенная задняя
```

## Требования к потоку анализа (критично!)

Поток для анализа **не должен сжиматься и терять FPS**: какого размера/FPS/bitrate
камера отдаёт — такое и анализируется. Реализация:

1. **Разрешение** — выбирается максимальный нативный размер из
   `StreamConfigurationMap` для output формата анализа (для внешних UVC-камер
   учитывается компромисс с поддерживаемым диапазоном FPS — см. Known issues).
2. **FPS** — `CONTROL_AE_TARGET_FPS_RANGE` фиксируется на нативный максимум
   (`setCaptureRequestFPS`), без понижающих ограничений приложения.
3. **Без дропа кадров** — в `OnImageAvailableListener` используется
   `reader.acquireNextImage()` (а НЕ `acquireLatestImage()`): каждый кадр камеры
   попадает в конвейер; сериализация инференса идёт через очередь ожидания
   `computingDetection`, а не через отбрасывание кадров.
4. **Без пережатия** — YUV→RGB конвертация в полный размер кадра; даунскейл
   выполняется только внутри классификатора до `imgsz` модели (это часть инференса,
   поток при этом сохраняется нативным). Bitrate актуален только для RTSP-режима
   (`trial/RTSPActivity`) — там транскодирование не выполняется, поток пробрасывается как есть.
5. **Мониторинг** — логгер считает incoming vs processed кадры; рост разницы
   означает, что инференс не успевает за камерой (см. Troubleshooting «drop-rate»).

## Известная проблема (решение не принято)

Для некоторых внешних UVC-камер «максимальное разрешение» и «максимальный FPS»
лежат в разных режимах сенсора (напр. 4K@15fps против 1080p@60fps). Текущий код
берёт максимальное разрешение; если тактический приоритет — FPS, нужен выбор
режима по произведению или отдельная настройка. Обсудить с заказчиком.
